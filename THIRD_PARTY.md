# Third-party components of the Zell toolchain archive

The toolchain archive (`scripts/package-toolchain.sh`) is self-contained:
besides Zell's own code (`bin/zell`, `bin/zell-lsp`, `bin/zell-mcp`, `std/`,
`targets/*/libzell_rt.a`, MIT licence, see the repository) it carries the
linker and the per-target link inputs below. Every download is pinned by
URL and SHA-256 in `scripts/bundle-targets.sh` and `scripts/build-lld.sh`;
`targets/SOURCES.sha256` in the archive lists them. How they are used:
docs/PLATFORMS.md, "Дистрибутив".

| Component | Where in the archive | Version, origin | Licence |
|---|---|---|---|
| LLVM lld (ELF, COFF/MinGW, Mach-O drivers) and the LLVM libraries it links | `bin/lld` (+ `ld.lld`, `ld64.lld`, `lld-link` links) | LLVM 18: Linux, macOS: `scripts/lld/lld-main.cpp` linked against the distribution's static LLVM 18 + lld libraries (Ubuntu 24.04 `llvm-18-dev`, `liblld-18-dev` 18.1.3; Homebrew `llvm@18`), or built from `llvm-project-18.1.8.src.tar.xz`; Windows: `lld.exe` of the official `clang+llvm-18.1.8-x86_64-pc-windows-msvc.tar.xz` | Apache-2.0 WITH LLVM-exception |
| zlib, zstd (statically in `bin/lld` on Linux; zstd on macOS) | `bin/lld` | Ubuntu 24.04 `zlib1g-dev` 1.3, `libzstd-dev` 1.5.5; Homebrew `zstd` | zlib; BSD-3-Clause |
| ncurses terminfo (statically in `bin/lld` on Linux) | `bin/lld` | Ubuntu 24.04 `libncurses-dev` 6.4 | MIT-style (X11) |
| libstdc++, libgcc (statically in `bin/lld` on Linux) | `bin/lld` | GCC 13 (Ubuntu 24.04) | GPL-3.0 WITH GCC-exception-3.1 |
| compiler-rt builtins and crtbegin/crtend | `targets/*/libclang_rt.builtins.a`, `targets/*-linux-*/crtbegin*.o`, `crtend*.o` | `compiler-rt-18.1.8.src.tar.xz` (LLVM release), compiled by `bundle-targets.sh` | Apache-2.0 WITH LLVM-exception |
| GNU C Library: crt objects, `libc_nonshared.a` | `targets/*-linux-gnu/{Scrt1,crt1,crti,crtn}.o`, `libc_nonshared.a` | glibc 2.31, Ubuntu 20.04 `libc6-dev` 2.31-0ubuntu9 (amd64, arm64) | LGPL-2.1-or-later (these objects carry the LGPL's linking exception for the startup files) |
| glibc link stubs | `targets/*-linux-gnu/lib{c,m,pthread,dl,rt,util}.so`, `ld-linux-*.so.*` | generated by `bundle-targets.sh` from the dynamic symbol tables (names, types, sizes, `GLIBC_2.x` versions) of Ubuntu 20.04 `libc6` 2.31-0ubuntu9; no glibc code | symbol lists of LGPL-2.1-or-later libraries |
| SQLite link stub | `targets/*-linux-gnu/libsqlite3.so` | generated from Ubuntu 24.04 `libsqlite3-0` 3.45.1 (symbol names only); the header `sqlite3.h` of `libsqlite3-dev` 3.45.1 is used to build the runtime | public domain |
| Linux kernel UAPI headers (runtime build only, not shipped) | — | Ubuntu 20.04 `linux-libc-dev` 5.4.0-26.30 | GPL-2.0 WITH Linux-syscall-note |
| musl libc | `targets/*-linux-musl/libc.a`, `crt1.o`, `rcrt1.o`, `Scrt1.o`, `crti.o`, `crtn.o` | musl 1.2.5 (`musl_1.2.5.orig.tar.gz` of the Ubuntu archive = upstream release), compiled by `bundle-targets.sh` | MIT |
| mingw-w64 CRT and import libraries | `targets/x86_64-pc-windows-gnu/crt2.o`, `dllcrt2.o`, `libmingw32.a`, `libmingwex.a`, `libmoldname.a`, `libmsvcrt.a`, `lib<dll>.a` | mingw-w64 11.0.1, Ubuntu 24.04 `mingw-w64-x86-64-dev` 11.0.1-3build1 (headers: `mingw-w64-common`, runtime build only) | ZPL-2.1 and public domain (mingw-w64 COPYING.MinGW-w64-runtime); import libraries are interface descriptions |
| macOS `libSystem.tbd` | `targets/*-apple-darwin/libSystem.tbd` | generated by `bundle-targets.sh`: the C symbol names the runtime imports plus `scripts/lld/darwin-symbols.txt`; no Apple code or SDK files | — (a list of public C API names) |
| Microsoft Visual C++ runtime (Windows archive only) | `bin/vcruntime140.dll`, `bin/vcruntime140_1.dll`, `bin/msvcp140.dll` | Visual C++ 2015-2022 redistributable of the build machine (GitHub `windows-latest`) | Microsoft Visual C++ redistributable licence (distributable code, may be shipped with applications) |

Executables that `zell build` links contain code from the runtime, from
compiler-rt (Apache-2.0 WITH LLVM-exception: no attribution required for
binaries), and, for musl targets, musl (MIT) and for Windows the mingw-w64
startup code (ZPL/public domain). glibc, msvcrt.dll and libSystem are linked
dynamically and come from the system the program runs on.

The `toolchain-inputs` release (built by the manual workflow `.github/workflows/inputs.yml`; `scripts/bundle-targets.sh --prebuilt`, `scripts/build-lld.sh --prebuilt`) redistributes exactly the components above, built from the same pinned sources and packaged in the same archives, under the same licences; it is a build cache for the release workflows, not an additional distribution channel.
